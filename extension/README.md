# เล่านิยาย · Local Thai Reader

Chrome Extension Manifest V3 มีแผงควบคุมภาษาไทย เล่นเสียงใน offscreen document ปิดแผงหรือเปลี่ยนแท็บแล้วยังฟังต่อได้

## ติดตั้ง

1. เปิด `chrome://extensions` แล้วเปิด Developer mode
2. กด Load unpacked แล้วเลือกโฟลเดอร์ **extension/dist** เช่น `D:\ProJectNextLevel\extension_read_novael\extension\dist`
3. เริ่ม `local-tts/start.ps1` แล้วเปิด Extension ผ่านไอคอนบนแถบเครื่องมือ
4. กด ⚙ ใส่ Token จาก `local-tts/.token` แล้วบันทึก
5. เปิด [นิยายตัวอย่าง](https://og-thai.blogspot.com/2022/04/1221.html) กด **อ่านบทนี้**

รุ่น **1.0.5** แยก `reader-background.js` สำหรับเปิดแผงจาก `reader-runtime.js` ที่จัดการอ่านเสียง ตัวเปิดแผงลงทะเบียน event ก่อนโหลดระบบเสียง และรายงานข้อผิดพลาดเริ่มต้นในแผงได้ ใช้ชื่อไฟล์ background ใหม่เพื่อให้ Chrome ลงทะเบียน entry ใหม่ หลังอัปเดตให้กด Reload ที่ chrome://extensions แล้วตรวจเลขเวอร์ชัน 1.0.5 การอัปเดตคงการตั้งค่าและตำแหน่งอ่านเดิมไว้

`npm run build` ใช้ TypeScript กับ esbuild สร้าง JavaScript แต่ละไฟล์แบบรวมครบในตัว พร้อม HTML/CSS ปกติ ไม่ใช้ Vite ในขั้น build หรือ dev server เปิด Chrome Extension จาก `dist` ได้ทันที มี Vite เป็น dependency ทางอ้อมของ Vitest สำหรับรันทดสอบเท่านั้น Chrome ไม่โหลด Vite

ทดสอบการคลิกไอคอนจริงด้วย Google Chrome ที่ติดตั้งในเครื่อง โดยใช้โปรไฟล์ใหม่แยกบน D: `npm run test:chrome-action` ครอบคลุมการเปิดแผงจากไอคอน และการกู้ค่าการเปิดแผงหลังรีโหลดจากการตั้งค่าแบบเก่า รายงานอยู่ `reports/chrome-action-e2e.json` การทดสอบใช้ Chrome DevTools Protocol เฉพาะโปรไฟล์ทดสอบ ไม่แก้ไขโปรไฟล์ผู้ใช้

`npm run test:bootstrap` จำลองให้ระบบอ่านเสียงเสียตอนเริ่มต้น เพื่อตรวจว่าตัวเปิดแผงยังทำงานและแสดงสาเหตุในแผงได้

เลือกเสียง ความเร็ว ระดับเสียง และเปิด/ปิดอ่านตอนถัดไปได้ในแผง ดึงเนื้อหาอัตโนมัติเฉพาะ OG Thai เว็บอื่นให้ลากเลือกข้อความก่อนแล้วกด **อ่านข้อความที่เลือก** Chrome ไม่อนุญาตให้ฉีดสคริปต์ในหน้า `chrome://` และบางหน้าเฉพาะของเบราว์เซอร์

ใน ⚙ มีตัวเลือก **Gemini ช่วยเตรียมคำอ่าน** ปิดเป็นค่าเริ่มต้น เมื่อต้องการใช้ให้กรอก API key จาก [Google AI Studio](https://aistudio.google.com/apikey) เลือกโมเดล (เริ่มต้น `gemini-3.5-flash-lite`) แล้วกด **ทดสอบคำอ่าน** และ **บันทึกและเชื่อมต่อ** API key คนละรหัสกับ Token ของ Local Server และเก็บไว้ที่ `local-tts/.gemini.json` บน D เท่านั้น ไม่เก็บใน Chrome storage ช่อง key ว่างหมายถึงใช้รหัสที่บันทึกไว้

เมื่อเปิด Gemini จะส่งข้อความนิยายไป Google โดยแบ่งทั้งหน้าเป็น **4 ชุดใหญ่** เปลี่ยนเป็น 3 ชุดได้ใน “แบ่งส่ง Gemini ต่อหน้า” ข้อความสั้นไม่เกิน 1,500 ตัวอักษรใช้ครั้งเดียว แต่ละชุดส่งเมื่อคิวเสียงอ่านใกล้ถึงและใช้ผลร่วมกันกับทุกช่วงเสียงในชุด แคชคำอ่านบน D ช่วยให้กลับมาอ่านหน้าเดิมโดยไม่เรียก API ซ้ำ แสดงความคืบหน้า “คำอ่าน x/y ชุด” ในแผง ปุ่มทดสอบคำอ่านใช้คำขอแยกจากการอ่านหน้า

ต้องใช้อินเทอร์เน็ตและอาจมีค่าใช้จ่ายตามบัญชี API เสียงยังสร้างในเครื่องที่ 48 steps สำหรับ F5 ข้อความต้นฉบับไม่เปลี่ยน และคำอ่านที่คุณกำหนดเองมีความสำคัญสูงสุด ถ้า API ขัดข้องจะหยุดพร้อมสาเหตุ ปิดสวิตช์แล้วบันทึกเพื่อกลับไปใช้ในเครื่องทั้งหมด ปุ่มลบ API key จะปิดสวิตช์ด้วย การเปลี่ยนการตั้งค่า Gemini ยกเลิกคิวเสียงเดิมและสร้างใหม่จากย่อหน้าปัจจุบัน การแบ่งชุดลดจำนวนคำขอแต่ไม่สามารถแก้การหมดโควตารายวันของบัญชีได้

เมื่อเปลี่ยนไปเว็บอื่น ให้คลิกไอคอน Extension บนแท็บนั้นก่อนหนึ่งครั้งเพื่อให้ Chrome มอบสิทธิ์ `activeTab` แล้วจึงเลือกข้อความและใช้ปุ่มในแผง

เสียงเริ่มต้นคือ **Thonburian** หลังผ่านการเล่นต่อเนื่อง 30 นาทีบนเครื่องนี้ หากติดตั้งเฉพาะ Vachana ระบบจะเลือกเสียงผู้หญิง 1 ที่พร้อมใช้แทน ยังเลือกสลับเสียงเองได้ และควรฟังคลิปใน `local-tts/reports/compare.html` เพื่อเลือกความเพราะที่ตรงใจ

กดพักแล้วกลับมาเล่นต่อได้ ระบบคืน offscreen หลังพักหรือหยุด 30 วินาที เมื่อใช้อีกครั้งจะสร้างใหม่และคืนตำแหน่งเดิม ขณะเตรียมโมเดลหรือเล่น WAV ผ่าน Blob URL จะเก็บตัวเล่นไว้แม้ปิดเสียง บันทึกตำแหน่งประมาณทุก 2 วินาทีและเมื่อเปลี่ยนสถานะ เปิดบทเดิมซ้ำจะคืนตำแหน่งเมื่อข้อความ เสียง และพจนานุกรมยังตรงกัน หลังเปิด Chrome ใหม่ต้องกดเล่นเอง

เมื่อกลับมาเล่นหลังรีสตาร์ต ระบบจะเชื่อมกับแท็บ OG Thai ที่เปิดอยู่ หรือเปิดต้นฉบับในแท็บเบื้องหลังหากไม่มี เพื่อใช้ไฮไลต์และอ่านตอนถัดไปต่อได้ ส่วนข้อความที่เลือกจากเว็บอื่นยังเล่นจากข้อความที่บันทึกไว้ได้

ระบบต่อบทใช้ลิงก์ Next ของหน้าเดิม เปิดตอนใหม่ในแท็บนิยายเดิม ตรวจลิงก์ซ้ำและปลายทาง OG Thai เท่านั้น หากปิดแท็บ โหลดไม่สำเร็จ หรือไม่มีตอนถัดไปจะหยุด หากเปลี่ยน URL ในแท็บด้วยตนเองระหว่างฟัง เสียงบทที่โหลดไว้ยังเล่นต่อได้ แต่ไฮไลต์จะทำงานเฉพาะ URL ที่ตรงกับบท

## พัฒนาและทดสอบ

```powershell
npm ci
npm test
npm run build
```

โหลด `dist` ใหม่ใน Chrome หลัง build โค้ดทั้งหมดรวมอยู่ใน Extension ไม่มี CDN หรือ remote script

ถ้า Chrome แจ้งว่าโหลด service worker ไม่ได้ ให้รัน `npm run build` จาก `extension` ก่อน แล้วกด Reload ที่ `chrome://extensions` และปิด/เปิดแผงใหม่ `dist/manifest.json` ต้องใช้ `"background": {"service_worker": "reader-background.js"}` โดยมี `reader-background.js`, `reader-runtime.js` และ `panel.html` ใน `dist` เดียวกัน ส่วน `extension/manifest.json` ที่ build สร้างให้จะใช้ `dist/reader-background.js` และ `dist/panel.html` อย่าคัดลอก manifest ข้ามโฟลเดอร์เอง หากยังโหลดไม่ผ่าน ให้เก็บข้อความในกล่องข้อผิดพลาดของ Chrome ทั้งกล่อง รวมบรรทัด Service worker / Status code เพื่อระบุสาเหตุจริง

ถ้าขึ้น `Service worker registration failed. Status code: 2` ให้ตรวจพื้นที่ว่างของไดรฟ์ที่เก็บโปรไฟล์ Chrome ด้วย แม้ตัว Extension อยู่บน D แต่โปรไฟล์ปกติยังอยู่บน C ในเครื่องนี้ตรวจพบ C ว่าง 0 ไบต์ ขณะที่การทดสอบที่ใช้โปรไฟล์บน D ผ่าน จึงต้องคืนพื้นที่และเริ่ม Chrome ใหม่ก่อนประเมินข้อผิดพลาดต่อไป ปิด Chrome ทุกหน้าต่างแล้วรันจากรากโปรเจกต์:

```powershell
powershell -ExecutionPolicy Bypass -File .\local-tts\repair-chrome-cache.ps1
```

สคริปต์คัดลอกแคช `Cache` และ `Code Cache` ของ Default profile ไป `D:\AI_Cache\chrome-cache\Default` ตรวจ SHA256 ก่อนนำสำเนาบน C ออก แล้วสร้าง junction ให้ Chrome ใช้ D ต่อไป สคริปต์หยุดหาก Chrome ยังทำงานอยู่ จากนั้นเปิด Chrome แล้ว Reload Extension อีกครั้ง

ใช้ `npm run test:manifest` เพื่อตรวจการลงทะเบียน service worker การเปิดแผง และการสร้าง offscreen document จริงใน Chromium สำหรับโฟลเดอร์ `dist`, `public` และ `extension` รายงานอยู่ `reports/manifest-e2e.json` ใช้โปรไฟล์แยกบน D และไม่เรียกใช้โมเดลเสียงหรือ API key ของผู้ใช้

ทดสอบจริงด้วย Chromium ที่แยกโปรไฟล์จาก Chrome ส่วนตัว:

```powershell
npx playwright install chromium
node tests/e2e.mjs
```

สคริปต์เริ่ม Local TTS ชั่วคราวเอง จึงต้องหยุดเซิร์ฟเวอร์ที่ใช้พอร์ต 8765 ก่อนทดสอบ รายงานอยู่ `reports/e2e.json` และภาพแผง `reports/panel.png` ทดสอบการจับคู่ token, อ่านเว็บจริง, พักเกิน 30 วินาที, ปิด offscreen, รีสตาร์ตเบราว์เซอร์, ต่อบท และปิดการเชื่อมต่อภายนอก

ทดสอบ Gemini ผ่าน Chromium และ FastAPI จริง โดยจำลอง Google และเสียง ไม่ใช้ API key จริงหรือเสียโควตา:

```powershell
node tests/gemini-e2e.mjs
```

ใช้เซิร์ฟเวอร์แยกพอร์ต 8766 และโปรไฟล์ชั่วคราวบน D ไม่แตะเซิร์ฟเวอร์เดิมพอร์ต 8765 รายงานอยู่ `reports/gemini-e2e.json` และภาพ `reports/gemini-settings.png` การเรียก Gemini จริงยังต้องทดสอบผ่านปุ่มในหน้าตั้งค่าด้วย key และสิทธิ์โมเดลของผู้ใช้

npm cache ใช้ `D:\AI_Cache\npm` ตาม `.npmrc` เบราว์เซอร์และโปรไฟล์ทดสอบใช้ `D:\AI_Cache\playwright` และ `D:\AI_Cache\browser-profiles` หากดาวน์โหลดเบราว์เซอร์ใหม่ ให้ตั้ง `$env:PLAYWRIGHT_BROWSERS_PATH = 'D:\AI_Cache\playwright'` ก่อน `npx playwright install chromium`

ทดสอบฟังจริงต่อเนื่อง 30 นาที:

```powershell
$env:NOVEL_SOAK_MINUTES = '30'
$env:NOVEL_SOAK_VOICE = 'thonburian:reference' # หรือ vachana:th_f_1
node tests/e2e.mjs
```

มีสิทธิ์เข้าถึง OG Thai สำหรับอ่านต่อบท สิทธิ์เข้าถึง loopback สำหรับ Local API และ `activeTab` สำหรับอ่านข้อความที่เลือกบนเว็บอื่น ข้อมูลนิยายและ token เก็บใน Chrome storage บนเครื่อง ประวัติตำแหน่งเก็บล่าสุด 30 หน้า
