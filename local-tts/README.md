# ระบบเสียงนิยายบนเครื่อง

Python 3.10 บน Windows; แยก environment `.venv` ไว้ในโฟลเดอร์นี้ ไม่ติดตั้งแพ็กเกจใน Python หลัก เริ่มจาก Vachana ผู้หญิงสองเสียงบน CPU เพื่อให้มีเสียงพร้อมใช้งานแม้ VRAM 4 GB

## เริ่มใช้งาน

เปิด PowerShell ในโฟลเดอร์นี้:

หยุดเซิร์ฟเวอร์ด้วย Ctrl+C ก่อนติดตั้งหรืออัปเดต เพื่อไม่ให้ Windows ล็อกไฟล์แพ็กเกจและโมเดลที่กำลังใช้งานอยู่

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

เปิดไฟล์ `.token` แล้วคัดลอกค่าไปใส่ในปุ่มตั้งค่าของ Extension หนึ่งครั้ง เก็บหน้าต่างเซิร์ฟเวอร์ไว้ขณะฟัง กด Ctrl+C เพื่อหยุด API ฟังเฉพาะ `127.0.0.1:8765` และต้องส่ง `Authorization: Bearer <token>` ทุก endpoint

แคชส่วนกลางและไฟล์ชั่วคราวใช้ **`D:\AI_Cache`**: Hugging Face, Torch, pip, Matplotlib, Numba และ temp ส่วนไฟล์เสียงแคชอยู่ `local-tts/cache` บน D เช่นกัน เปลี่ยนฐานแคชได้ด้วย `NOVEL_CACHE_HOME` ก่อนเริ่มโปรแกรม ไม่ต้องใช้พื้นที่แคชบน C

สคริปต์ดาวน์โหลดโมเดลต้องใช้อินเทอร์เน็ต เมื่อดาวน์โหลดครบการสร้างเสียงจะอ่านไฟล์ local เท่านั้น `HF_HUB_OFFLINE=1` และ `TRANSFORMERS_OFFLINE=1` ถูกตั้งขณะเริ่มบริการ โมเดล น้ำหนัก และเสียงอ้างอิงอยู่ในโฟลเดอร์นี้

## เสียงคุณภาพ F5

Thonburian และ OpenJai ใช้การสร้างเสียง **48 steps** เพิ่มจากเดิม 24 steps เพื่อทดลองคุณภาพ โดยใช้เวลาสร้างมากขึ้น ค่าจำนวน steps เป็นส่วนหนึ่งของคีย์แคช จึงสร้างเสียงใหม่แทนการนำเสียง 24 steps กลับมาใช้ หลังแก้ค่านี้ให้หยุดและเริ่มเซิร์ฟเวอร์ใหม่ แล้วกด “อ่านบทนี้” เพื่อเริ่มงานใหม่

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -Profile thonburian
```

ติดตั้ง PyTorch CUDA 12.1 และ FlowTTS ลง `.venv` เดียวกัน โหลดโมเดลทีละเสียง ตัวติดตั้งใช้พื้นที่ชั่วคราวบนไดรฟ์เดียวกับโปรเจกต์เพราะ wheel ของ CUDA มีขนาดใหญ่ ต้องมี Git, FFmpeg และไดรเวอร์ NVIDIA ที่รองรับ หากไม่มีเสียงอ้างอิงจะสร้างตัวอย่างผู้หญิงจาก Vachana พร้อมข้อความถอดเสียง โดยไม่โหลด Whisper

หากต้องการใช้เสียงอ้างอิงของคุณเอง ให้วาง WAV เสียงชัด 6–12 วินาทีที่มีสิทธิ์ใช้ใน `voices/` คัดลอก `reference.example.json` เป็น `reference.json` ใส่ชื่อไฟล์ ข้อความตรงกับเสียง แหล่งที่มา และเงื่อนไขสิทธิ์ แล้วเริ่มเซิร์ฟเวอร์ใหม่

OpenJai เป็นตัวเปรียบเทียบที่ต้องได้รับสิทธิ์จากเจ้าของโมเดลก่อน เปิด [หน้าโมเดล](https://huggingface.co/JTS-AI/OpenJaiTTS-v1.0) และขอสิทธิ์ เมื่ออนุมัติแล้วตั้ง `HF_TOKEN` ใน PowerShell บนเครื่องก่อนเรียก `setup.ps1 -Profile openjai` ห้ามนำ token นี้ใส่ใน Extension; Extension ใช้ `.token` ของระบบเสียงเท่านั้น การดาวน์โหลดไม่สำเร็จจะไม่ทำให้เสียง Vachana ที่ติดตั้งแล้วเสียไป

## คลิปเปรียบเทียบและการตรวจสอบ

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.benchmark --offline
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
```

เปิด `reports/compare.html` เพื่อฟังข้อความเดียวกัน 12 ชุดต่อเสียง เลือกหมายเลขข้อความเพื่อฟังเทียบ และกรอกความเพราะ คำผิด/ข้าม/ซ้ำพร้อมบันทึกความเห็น ผลฟังเก็บในเบราว์เซอร์และส่งออกเป็น JSON ได้ ผลเวลาและ RTF อยู่ใน `reports/benchmark.json` ค่า RTF ต่ำกว่า 1 หมายถึงสร้างเสียงเร็วกว่าความยาวเสียง บรรทัดแรกของแต่ละเสียงรวมเวลาโหลดโมเดลด้วย รายงานจะไม่ให้คะแนนความเพราะ คำผิด หรือ CER แทนผู้ฟัง

พจนานุกรมคำอ่านตั้งได้ใน Extension ตัวอย่าง `ลอเอล=ลอ เอล` หนึ่งคู่ต่อบรรทัด เปลี่ยนเฉพาะข้อความส่งเข้าโมเดล ข้อความที่แสดงและตำแหน่งย่อหน้ายังคงเป็นต้นฉบับ

## Gemini ช่วยเตรียมคำอ่าน (เลือกเปิดได้)

รีสตาร์ต Local Server และโหลด Extension ซ้ำหลังอัปเดต เปิด ⚙ แล้วเปิด “ใช้ Gemini ก่อนสร้างเสียง” โมเดลเริ่มต้น `gemini-3.5-flash-lite` เปลี่ยนชื่อโมเดลได้ตามสิทธิ์ของบัญชี กรอก API key จาก [Google AI Studio](https://aistudio.google.com/apikey) ซึ่งเป็นคนละรหัสกับ `.token` กด “ทดสอบคำอ่าน” เพื่อทดสอบข้อความตัวอย่าง แล้ว “บันทึกและเชื่อมต่อ” เพื่อใช้กับนิยาย

ปุ่มทดสอบจะบันทึก API key ใหม่ที่กรอกไว้และส่งเฉพาะข้อความตัวอย่าง ไม่เปิดสวิตช์อ่านนิยายผ่าน Gemini ให้เอง ช่อง key ว่างหมายถึงใช้รหัสเดิม ปุ่ม “ลบ API key” จะปิดการใช้ Gemini และลบรหัสจาก Server

เมื่อเปิดใช้ จะแบ่งข้อความทั้งหน้าเป็น **4 ชุดใหญ่** ตามจำนวนตัวอักษร เลือกเปลี่ยนเป็น 3 ชุดได้ใน Extension ข้อความสั้นไม่เกิน 1,500 ตัวอักษรใช้ชุดเดียว ส่งแต่ละชุดไป `generativelanguage.googleapis.com` เพื่อขอรายการคำ/คำอ่านเมื่อคิวเสียงอ่านใกล้ถึงชุดนั้น แล้วใช้รายการเดียวกันกับทุกช่วงเสียงในชุด ไม่เรียก API ซ้ำทีละช่วงเสียง ชุดที่อ่านแคชได้ไม่ใช้โควตาเพิ่ม ปุ่มทดสอบคำอ่านเป็นการเรียก API เพิ่มต่างหาก หากเริ่มอ่าน/เลื่อนข้ามจะส่งเฉพาะชุดที่จำเป็นต่อคิว

ไม่ส่งเสียงหรือ Token ของ Local API ข้อความบนหน้าและลำดับย่อหน้ายังเป็นต้นฉบับ ตรวจว่าคำที่แก้มีอยู่ในข้อความชุดนั้นจริงแล้วแทนที่เฉพาะคำนั้น พจนานุกรมที่ผู้ใช้กำหนดมีสิทธิ์เหนือคำแนะนำจาก Gemini รวมถึงกรณีวลีของ Gemini ทับชื่อที่ตั้งไว้ โมเดลภาษาอาจเสนอคำอ่านผิดได้ ควรฟังและแก้ชื่อสำคัญด้วยพจนานุกรม

API key บันทึกใน `local-tts/.gemini.json` บน D แยกจาก Chrome storage และไม่ได้ส่งกลับผ่าน API หรือบันทึกในงาน/รายงาน ไฟล์นี้เป็นความลับบนเครื่องและถูกยกเว้นจาก Git ผลคำอ่านแคชใน `local-tts/cache/pronunciation` บน D จำกัด 50 MB แยกตามโมเดล ข้อความแต่ละชุด และเวอร์ชันคำสั่ง เพื่อลดการเรียกซ้ำ จำนวนชุดและข้อความเดิมจะใช้แคชเดิมเมื่อเปิดหน้าเดิมอีกครั้ง ไม่มีการเปลี่ยนโมเดลอัตโนมัติ การแบ่งชุดลดจำนวนคำขอ แต่ไม่เพิ่มโควตารายวันหรือโควตา token ของบัญชี

ต้องใช้อินเทอร์เน็ตเมื่อยังไม่มีคำอ่านในแคช และอาจมีค่าใช้จ่าย/ข้อจำกัดโควตาตามบัญชี Google เมื่อ API หมดเวลา คำอ่านไม่ผ่านการตรวจ หรือเกินโควตา งานจะหยุดพร้อมสาเหตุ ไม่มีการย้อนกลับไปอ่านคำเดิมโดยเงียบ ๆ ปิดสวิตช์แล้วบันทึกเพื่ออ่านในเครื่องทั้งหมด งานเก่าที่ถูกยกเลิกจะไม่นำผล API ที่กลับมาภายหลังไปสร้างหรือเล่นเสียง แต่คำขอที่ส่งไปแล้วอาจยังถูก Google ประมวลผล

ทดสอบการเชื่อมต่อจริงต้องใช้ API key ของผู้ใช้ การทดสอบในชุดโค้ดใช้ HTTP จำลองและไม่เรียก Google หรือเสียโควตา

## API

| Method / Path | Input / Output |
|---|---|
| `GET /health` | สถานะ โมเดลที่อยู่ในหน่วยความจำ อุปกรณ์ |
| `GET /voices` | รายการเสียง `id`, `ready`, `reason`, `device`, `license` |
| `GET /gemini` | สถานะว่ามี key และ revision; ไม่คืน key |
| `POST /gemini` | `{api_key: string}` → เก็บ key ในเครื่อง |
| `DELETE /gemini` | ลบ key ในเครื่อง |
| `POST /gemini/test` | `{model: string}` → ตัวอย่างต้นฉบับและคำอ่าน; ใช้ API จริงโดยไม่อ่านแคช |
| `POST /jobs` | `{paragraphs: string[], voice, start_paragraph?: 0, dictionary?: {}, gemini?: {enabled: false, model: "gemini-3.5-flash-lite", batches: 4}}` → งานและ chunks; batches เลือก 3 หรือ 4 |
| `GET /jobs/{id}` | `id`, `state`, `error`, `chunks[]` ที่มี index, paragraph, text, ready, seconds และ `pronunciation` แสดงจำนวนชุดทั้งหมด/ที่พร้อม |
| `POST /jobs/{id}/cursor` | `{index: number}` → เลื่อนหน้าต่างเตรียมเสียง 3 ช่วง |
| `GET /jobs/{id}/chunks/{index}` | WAV; 409 เมื่อยังไม่พร้อม, 410 เมื่อยกเลิก |
| `DELETE /jobs/{id}` | ยกเลิกงาน; ผลลัพธ์ที่กำลังสร้างจะไม่ถูกเผยแพร่ |

มีเซสชันอ่านครั้งละหนึ่งรายการ งานใหม่ยกเลิกงานเดิม เสียงถูกแคชตามโมเดล/เสียง/ข้อความที่แก้คำอ่านแล้ว แคชมีงบ 2 GB และลบไฟล์เก่าที่ไม่ถูกงานใช้อยู่ งานเก่าหมดอายุภายในหนึ่งชั่วโมงและเก็บไม่เกิน 20 รายการ ไฟล์งานที่กำลังใช้งานจะไม่ถูกลบทิ้ง หากบทเดียวใหญ่เกินงบแคชสามารถเกินงบชั่วคราวจนยกเลิกงาน

หากพบ CUDA out of memory ระบบลองแบ่งข้อความสั้นลงอีกหนึ่งครั้ง หากยังล้มเหลวจะแจ้งให้เลือก Vachana เอง เพื่อไม่เปลี่ยนน้ำเสียงกลางบท

Vachana ตรวจข้อความหลังล้างเครื่องหมายก่อนแปลงคำอ่าน ช่วงที่เหลือว่างหรือมีแต่เครื่องหมาย เช่น `---`, `***`, `“”` จะเป็นจังหวะพัก 0.2 วินาทีแล้วอ่านต่อ โดยข้อความบนหน้าไม่เปลี่ยน ส่วนคำจริงที่แปลงเสียงไม่ได้ยังแจ้งข้อผิดพลาดตามปกติ

# ทดลอง OmniVoice บนเครื่อง

ติดตั้งแยกด้วย `powershell -ExecutionPolicy Bypass -File .\local-tts\setup-omnivoice.ps1` จากโฟลเดอร์โปรเจกต์ แล้วใช้ `local-tts/start.ps1` ตามเดิม

- Environment: `local-tts/.venv-omni` (PyTorch 2.8 CUDA 12.8) แยกจาก F5/Vachana เดิม
- โมเดลและ audio tokenizer: `local-tts/models/omnivoice` โหลด revision ที่ล็อกใน `app/model_versions.json`
- ไฟล์ชั่วคราวและแคชติดตั้งอยู่ `D:/AI_Cache`; เสียงแคชยังอยู่ `local-tts/cache`
- เลือก **OmniVoice · ผู้หญิงอ้างอิง · 32 steps** ใน Extension; การตั้งค่าเสียงเดิมที่บันทึกไว้ไม่ถูกเปลี่ยนอัตโนมัติ
- ใช้ `voices/reference.wav` พร้อมข้อความถอดเสียงใน `voices/reference.json` เดิม เป็นเสียงผู้หญิงสังเคราะห์จาก Vachana ไม่ใช่เสียงนักพากย์จริง
- โหลดตัวรันแยกหนึ่งครั้งแล้วใช้ซ้ำในแต่ละช่วง สลับไปโมเดลอื่นแล้วปิดตัวรัน OmniVoice เพื่อคืน VRAM
- ตัวรันเสียงบล็อกการเชื่อมต่อเครือข่าย และไม่โหลด Whisper; Gemini คำอ่านยังเป็นตัวเลือกแยกตามการตั้งค่าเดิม
- 32 steps เป็นค่าของ OmniVoice; ค่า 48 steps ของ Thonburian ยังคงเดิม
- ทดสอบจริงด้วย `.venv/Scripts/python.exe -X utf8 -m app.omni_benchmark` ภายใน `local-tts` แล้วเปิด `reports/omnivoice.html` เพื่อฟัง 12 คลิปและดู `reports/omnivoice.json`

หากต้องการเปลี่ยนเสียงอ้างอิง ให้ใช้ WAV ภาษาไทยที่คุณมีสิทธิ์ใช้ ความยาว 3–10 วินาที แก้ข้อความถอดเสียงและข้อมูลแหล่งที่มาใน `reference.json` ให้ตรงเสียง แล้วรีสตาร์ต Local Server การเปลี่ยนนี้มีผลกับเสียงอ้างอิงของ F5 ด้วย
